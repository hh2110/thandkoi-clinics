# Plan 03.5 — Design System Enhancements & Page Layout Components

_Status: Drafted · Depends on: 03 Design system & base templates (merged) · Next: 04 Core content pages_

## Why this is 03.5 and not part of 03

Plan 03 shipped and is merged: tokens (light+dark), self-hosted type, the
theme toggle, base template, and the **chrome** — header, nav, footer, buttons,
cards. What it deliberately did *not* build is any **page-body layout
vocabulary**: there is no hero, no stat band, no service/card grid, no
feature split, no call-to-action band, no gallery grid, and no section-rhythm
system. Plan 04 (and 05/06) each need those, and without a shared set they'd
either invent their own per page — the exact "reinventing the shell each time"
that Plan 03 set out to prevent — or ship visually bare.

Rather than reopen a merged plan, this half-step extends the design system with
the reusable body components, so 04+ *compose* pages from a known kit instead of
hand-rolling layout. It is a pure design-system/template plan: **no page models,
no content, no data** (those stay in 04/06/08).

## Design reference

Two clickable mockups were produced to pin down the target look before writing
code — both built strictly on Plan 03's tokens, logo, type, and the
brand-guidelines colour rules (coral = cross/heart motif only; amber = Donate
only):

- **`Thandkoi Clinics Site`** — a faithful recreation of what renders *today*
  (chrome + the near-empty home shell), as the before-state baseline.
- **`Thandkoi Clinics Home (Proposed)`** — the target home page: sticky header,
  hero (headline + Zakat/Sadaqa CTA + Urdu tagline + floating stat card),
  impact-stat band, "What we do" service cards, latest-daily-report split,
  gallery-preview grid, and a Teal-Deep donate band. Both themes, working
  toggle.

These are the acceptance target for the components below. They are committed to
**[`docs/design/`](../../docs/design/)** — full-page PNGs (light + dark) plus the
interactive prototype sources under `docs/design/prototypes/` — so the reference
travels with the repo. See [`docs/design/README.md`](../../docs/design/README.md).

## Scope

**In scope**
- A **page-body layout kit** as CSS + reusable template partials, all built on
  Plan 03 tokens (zero new hard-coded colours, both themes + RTL for free):
  - **Section rhythm** — standard vertical spacing, `wrapper` max-width reuse,
    tinted vs. plain section backgrounds (`--color-accent-soft-bg`), and a
    Teal-Deep "dark band" section (the donate band / footer family).
  - **Hero** — two-column headline + intro + CTA cluster + optional media
    slot and floating stat card; collapses to one column on narrow screens.
  - **Impact-stat band** — a responsive row of number/label pairs, figures in
    Archivo with `tabular-nums`; numbers are template inputs, never hardcoded.
  - **Card grid** — the existing `.card` arranged in a responsive 2/3/4-up
    grid with an icon slot, heading, body, optional status tag ("Planned").
  - **Feature split** — media-beside-text block (used by the latest-report
    teaser and any "X beside a photo" section), reversible left/right.
  - **CTA band** — full-width Teal-Deep band with heading + primary action,
    for the Donate ask (amber CTA) and similar.
  - **Media/gallery grid** — responsive square grid of image slots.
  - **Eyebrow / section-header** pattern — uppercase 0.14em label + `h2`.
- **Image placeholder treatment** — a consistent striped placeholder with a
  monospace caption for "photo goes here", so pages look intentional before
  real photography lands (ties into Plan 04/06's photos-pending reality and
  the consent rule — placeholders carry no identifiable person).
- **Motion** — subtle, tasteful hover lift on interactive cards only, fully
  gated behind `prefers-reduced-motion` (Plan 03 already respects it); no
  scroll-jacking, no autoplay, no gradients/heavy shadow (brand §7 "Don't").
- Extend the smoke tests: any page using a section partial renders in both
  `/en/` and `/ur/`, both themes, with correct `lang`/`dir`.

**Out of scope** (other plans)
- Page models, fields, StreamField block *definitions*, and content → Plan 04
  (this plan provides the **templates** those blocks render through, so 04
  wires model→template rather than also authoring markup/CSS).
- Real numbers/photos/copy → CMS content entry (Plan 04 checklist) / Plan 08.
- Donate page, gallery page, reports page *models* → 05/06.

## Proposed decisions (confirm before building)

| Choice | Proposed | Notes |
|---|---|---|
| CSS location | New `static/css/layout.css` (loaded after `components.css` in `base.html`), not more sprawl in `components.css` | `components.css` stays "chrome + primitives"; `layout.css` is "page-body sections." One more `<link>`, no build step — consistent with Plan 03's no-framework decision. |
| How sections are reused | Django include partials under `templates/partials/sections/` (e.g. `hero.html`, `stat_band.html`, `card_grid.html`, `feature_split.html`, `cta_band.html`, `media_grid.html`), driven by context/block data | Plan 04's StreamField block templates `{% include %}` these, so the same markup serves a StreamField block and a plain view. No duplicate markup between "block" and "page." |
| Styling method | Hand-written CSS classes on semantic markup, tokens only | Matches merged Plan 03; keeps it readable for a Python-only maintainer. (The mockups use inline styles because of the prototyping tool — the real implementation is class-based CSS reading tokens, same values.) |
| Image placeholders | A `.media-placeholder` class (striped, captioned) used until a real image field is populated; template falls back to it when the image is unset | Pages never show a broken/empty box; dovetails with Plan 04's "renders correctly with fields unset" acceptance criterion. |
| Motion | Hover lift on `.card` (transform + shadow) only, `@media (prefers-reduced-motion: reduce)` removes it | Adds life without violating brand §7 (no gradients/heavy shadow/emoji). |
| Numbers & copy in components | Every figure, label, and string is a template variable — components ship with **no** baked-in numbers or prose | The mockups' "128 patients / sample figures" are illustrative only; real values come from the CMS/pipeline. |

## Proposed file additions

```
static/css/
└── layout.css                     # section rhythm + hero/stat/grid/split/cta/media
templates/partials/sections/
├── hero.html
├── stat_band.html
├── card_grid.html                 # + a card partial or block
├── feature_split.html
├── cta_band.html
├── section_header.html            # eyebrow + h2
└── media_grid.html
docs/design/                        # exported mockups as visual reference (optional)
```

`base.html` gains one `<link rel="stylesheet" href="{% static 'css/layout.css' %}">`
after `components.css`.

## Task checklist

1. **`layout.css` foundation** — section spacing scale, `.section--tinted`
   and `.section--dark` (Teal-Deep band) backgrounds, `.eyebrow` label, all via
   tokens; verify both themes and RTL (logical properties only).
2. **Hero partial + CSS** — two-column grid, CTA cluster, media slot, floating
   stat card; single-column under the components.css breakpoint.
3. **Stat-band partial + CSS** — responsive number/label row, `tabular-nums`,
   optional caption line; inputs are a list of `{value, label}`.
4. **Card-grid + card partial** — 2/3/4-up responsive grid, icon slot,
   optional `Planned` status tag; hover lift (reduced-motion gated).
5. **Feature-split partial** — media + text, `reverse` flag; used by the
   report teaser.
6. **CTA-band partial** — Teal-Deep band, heading + amber primary action +
   sub-note; amber only here + Donate (brand §2/§7).
7. **Media-grid + placeholder** — square responsive grid; `.media-placeholder`
   striped/captioned fallback when an image is unset.
8. **Wire into `base.html`** — add the `layout.css` link; confirm load order.
9. **Demo/preview** — a temporary styleguide view (or extend the existing home
   placeholder) that renders each section with dummy context, so the kit is
   reviewable before Plan 04 consumes it; removed/replaced when 04 lands.
10. **Tests** — each section partial renders without error given minimal
    context; a page composed of them returns 200 in both languages/themes with
    correct `lang`/`dir`; `.media-placeholder` shows when an image is absent.

## Acceptance criteria

- Plan 04 can build the Home page by composing these partials/classes without
  writing new section CSS or markup.
- Every component renders correctly in **both themes** and **both languages**
  (RTL mirrored) with zero per-component dark-mode or RTL overrides.
- No new hard-coded colours — `layout.css` reads only tokens; a token change
  reflows the whole kit.
- No baked-in numbers or copy in any component; all are template inputs.
- Sections with an unset image show the intentional placeholder, never a
  broken or empty box.
- Motion is present only on card hover and fully removed under
  `prefers-reduced-motion`.
- No third-party CSS/JS/font/CDN request added (Plan 03 privacy invariant).
- `ruff check` and `pytest` (incl. new section-render tests) pass in CI.
